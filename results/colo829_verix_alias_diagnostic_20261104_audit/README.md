# Audit of the COLO829 Verix alias diagnostic

The [analysis note](../../docs/research/2026-11-03-colo829-contig-alias-diagnostic.md)
defines the exploratory case, the initial failed gzip attempt, the successful
plain-input repeat and its limits. The two plain input files remain outside
Git; their source, regeneration, hashes, commands and raw native reports are
recorded in the two attempt packets.

`byte-diff.json` was produced by `analysis/verify_colo829_case_diff.py`, a
separate byte-comparison implementation. It checks line counts, all non-ALT
fields, exact ALT bytes outside the remote-contig token, and uniqueness of
the case-insensitive header match. The result is 66 case-only changes among
438 lines. It does not validate the scientific equivalence of the inputs.

`native-groups.json` was produced using the pinned Verix installation and
`analysis/audit_colo829_native_groups.py`. It records each native group and
whether its two records have reciprocal `MATEID` values. The original has
66 singletons; the case-normalized input has 33 such reciprocal pairs. The
native parser groups by its coordinate lookup; it is not said to use MATEID
for that grouping. `native-groups.stderr.txt` preserves its HTSlib warnings.

For reproduction, use the plain inputs regenerated by attempt 02:

```sh
python analysis/verify_colo829_case_diff.py /path/original.vcf /path/case-normalized.vcf
python analysis/audit_colo829_native_groups.py \
  --original /path/original.vcf --normalized /path/case-normalized.vcf
```

The second command requires the pinned Verix environment described by the
attempt receipt. These are main-agent checks; independent review is pending.
