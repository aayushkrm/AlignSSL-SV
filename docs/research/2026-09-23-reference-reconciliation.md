# HGSVC/IGSR GRCh38 reference reconciliation

**Date:** 2026-09-23. **Status:** publisher-verified HGSVC source, complete shared-contig digest comparison, and verified 18-contig base-difference map. HGSVC and IGSR references are not identical; cohort compatibility remains unresolved.

The [PAV reference documentation](https://github.com/EichlerLab/pav/blob/main/README.md) points to the [first-party HGSVC no-ALT reference](https://ftp.1000genomes.ebi.ac.uk/vol1/ftp/data_collections/HGSVC2/technical/reference/20200513_hg38_NoALT/). Its [README](https://ftp.1000genomes.ebi.ac.uk/vol1/ftp/data_collections/HGSVC2/technical/reference/20200513_hg38_NoALT/README_20200513_hg38_NoALT.txt) says this primary/unlocalized/unplaced reference, excluding ALT, patch, decoy, and HLA-ALT sequences, will be used throughout HGSVC long-read work. The [manifest](https://ftp.1000genomes.ebi.ac.uk/vol1/ftp/data_collections/HGSVC2/technical/reference/20200513_hg38_NoALT/MANIFEST_20200513_hg38_NoALT.txt) lists `hg38.no_alt.fa.gz` at 963,047,116 bytes with MD5 `6a5ceceed91ae5c14026454f09c4b6c4`, plus `.fai` and `.gzi` indexes. The exact per-contig M5 match below provides strong sequence-identity evidence, although it does not independently establish the calling pipeline's full provenance.

The cluster transfer is staged at `/scratch/igorno-alignssl_restart_20260922/hgsvc-noalt-reference` using [`cluster/stage_hgsvc_noalt_reference.sh`](../../cluster/stage_hgsvc_noalt_reference.sh). The 963,047,116-byte FASTA and its `.fai`/`.gzi` indexes all match the publisher's MD5 manifest; the README MD5 and gzip integrity also pass. The FASTA SHA-256 is `90f1dcdb28a81ac26f6eaa1afc285e7ec459c195c2134fb25af0e82be2f11729`. The reference comparison code is [`scripts/audit_reference_m5.py`](../../scripts/audit_reference_m5.py). It calculates, per FASTA contig, both the SAM/VCF-canonical MD5 (uppercase sequence, whitespace removed) and a case-preserving MD5, then compares the HGSVC3 SV VCF header with the [official IGSR sequence dictionary](https://ftp.1000genomes.ebi.ac.uk/vol1/ftp/technical/reference/GRCh38_reference_genome/GRCh38_full_analysis_set_plus_decoy_hla.dict). The dictionary copy staged on cluster has SHA-256 `91f7a9993b70c9c85b3a51a20b888d866cd55938ce1ccd3a325a38954d2fbdeb`.

The complete comparison covers **194 shared contigs**: all 194 FASTA lengths and canonical M5s match the HGSVC3 VCF header, whereas only 176 canonical M5s match the IGSR dictionary. All 194 lengths agree. The 18 IGSR mismatches are `chr1`, `chr2`, `chr3`, `chr5`, `chr6`, `chr7`, `chr9`, `chr10`, `chr12`, `chr13`, `chr14`, `chr16`, `chr17`, `chr19`, `chr21`, `chr22`, `chrX`, and `chrY`. The generated comparison is `all_contig_m5.json` in the same cluster reference directory. This complete identity with the VCF header strongly ties the downloaded HGSVC source to the VCF's reference sequences, while the absence of 18 IGSR M5 matches proves the two references are not identical under the SAM/VCF digest definition.

For chr1 specifically, the verified HGSVC FASTA's canonical M5 is `2648ae1bacce4ec4b6cf337dcae37816`, its case-preserving MD5 is `a004bc1b0bf05fc668cab6bbfd93d3eb`, and the IGSR dictionary and checked `HG00512` CRAM header give `6aef897c3d6ff0c78aff06ac189178dd`. Thus simple letter case does not explain this difference. A [GA4GH reference-collection discussion](https://github.com/ga4gh/refget/issues/1) independently uses the same chr1 digest as a reference-identity example; it is context, not proof of this HGSVC3 release's provenance.

The first base-level pass streamed all 18 sequence-distinct contigs and stored counts, difference types, and only the first 20 positions per contig as `*_base_differences.json` in the cluster reference directory. An independent [scientific review](2026-09-23-scientific-review-5762726.md) summed **13,923,221 different bases among 2,371,021,378 compared bases (0.587%)**. Six contigs (`chrY`, `chr19`, `chr5`, `chr22`, `chr21`, `chr14`) contain 13,923,135 of these; 13,923,127 bases overall are HGSVC A/C/G/T versus IGSR `N`, and 94 are HGSVC `N` versus IGSR ambiguity codes. The sparse chr1/chr10 differences do not characterize the whole genome. These observations suggest large reference-masking differences, but do not yet establish which truth records, read alignments, candidate windows, or flanks can be compared safely.

[`scripts/compare_reference_contig.py`](../../scripts/compare_reference_contig.py) and [`cluster/audit_reference_differences.sh`](../../cluster/audit_reference_differences.sh) generated complete coalesced BED3 mismatch intervals, with a SHA-256 checksum in each companion JSON. SLURM job `1598069` failed before reading sequence because an outdated `samtools` executable lacked `libcrypto.so.1.0.0` on `hydra-n12`; its log is retained. The working `bioinfo` `samtools` passed both local and remote 10-base queries, and replacement job `1598070` **completed** in 17m21s. The 18 full JSON/BED pairs, the original count-only JSONs, M5 comparison, source/hash notes, and both job logs are mirrored in [`results/reference_reconciliation/2026-09-23`](../../results/reference_reconciliation/2026-09-23). [`scripts/verify_reference_difference_map.py`](../../scripts/verify_reference_difference_map.py) checked all 18 BED SHA-256 digests, BED coordinate/order/merging invariants, interval lengths and counts, first recorded positions, and equality with the original JSON counts/types. [`VERIFICATION.json`](../../results/reference_reconciliation/2026-09-23/VERIFICATION.json) records file hashes and totals: **13,923,221 different bases in 152 BED intervals**, over 2,371,021,378 compared bases. These are sequence-difference intervals, not validated safe exclusion intervals.

The independent [map review](2026-09-23-scientific-review-reference-map.md) identified an important limit: the difference BED omits positions where **both** references are `N`. A 100-base gap between two chr14 BED intervals was directly confirmed to be shared `N`, so the BED is **not** a callability or safe-exclusion mask. The subsequent [full-reference ambiguity audit](2026-09-23-reference-ambiguity.md) now preserves a verified IGSR FASTA snapshot and complete per-reference non-ACGT BEDs. All 13,923,221 unequal bases fall within the 165,046,090-base joint ambiguity territory on the 194 shared contigs. This narrows the sequence discrepancy but does not create donor-specific confident-negative regions or demonstrate that mapping/candidate behavior is unchanged away from ambiguity. Next: audit overlap with truth loci, candidate windows/flanks and read evidence, and validate a predeclared donor/interval bridge or remapping strategy. Bulk IGSR CRAM transfer stays closed until the reference and callability gates are resolved. The GIAB HG002 v5.0q paired VCF/BED remains an immediate development benchmark, not independent confirmation.
