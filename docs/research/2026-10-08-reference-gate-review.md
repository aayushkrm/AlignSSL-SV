## Concrete strict-cap defect

P2: the NEW `_posthash` consumes `size` bytes, then calls `os.read(fd, 1)` to probe EOF. If a file began at `size == cap` and grows during that pass, the probe consumes one byte beyond the declared cap before rejection. This reintroduces the overflow-byte behavior removed from the census readers.
It fails the check rather than falsely passing altered data, and the fixed compressed reference size is below its cap; this is a strict resource-contract defect, not an observed genomic mismatch. The primitive also postchecks FAI/native/code files with their own caps.
Use a cap-bounded read plus size/hash/fstat/lstat checks, with no extra byte once the cap is exhausted. Add a grow-at-cap regression that checks the consumed-byte count and absence of a report. Do not modify the unchanged helper or run real data to test this.
