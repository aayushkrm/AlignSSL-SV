# Complex-SV allele evaluation: bounded opportunity scout

**Decision: one-event falsifier only.** There is a plausible, distinct question at the scale of long, multi-junction event topology. There is no evidence in this source-only pass that a public counterexample has already been demonstrated. Do not call this a new generic haplotype metric, a caller defect, or a confirmed opportunity until the falsifier below passes.

## What is already covered

| Prior art | What it actually evaluates | Boundary relevant here |
|---|---|---|
| [Truvari](https://doi.org/10.1186/s13059-022-02840-6) | Pairwise record matching by SV type, position/overlap, size, sequence, and genotype criteria. | A component/record score can be intentional. A mismatch in whole-event interpretation is not, by itself, a bug in this metric. |
| [phab](https://github.com/ACEnglish/truvari/wiki/phab) | Reconstructs phased haplotypes, aligns query and truth haplotypes, and recalls variants to harmonize representation. | Haplotype-level representation comparison is established prior art; phab is intended for phased calls and is not a discovery caller. |
| [vcfdist](https://doi.org/10.1186/s13059-024-03394-5), [official overview](https://github.com/TimD1/vcfdist/wiki/01-Overview), [usage](https://github.com/TimD1/vcfdist/wiki/02-Parameters-and-Usage) | Joint evaluation of phased SNPs, indels, and SVs by clustered haplotype sequence; handles complex representations and phase flip/switch errors. The paper gives a 145-bp deletion represented as 47+1+97-bp deletions. | This rules out novelty based on generic allele equivalence or local cis/trans phase. The official docs describe phased local SV evaluation up to 10 kb and caution that larger variants can require over 50 GB RAM. The paper filters inversion records in one runtime comparison because they skewed Truvari-refine timing; that is not evidence that vcfdist cannot evaluate inversions. The sources reviewed do not establish separately validated, scalable scoring of a complete long-INV or multi-junction derivative path. |
| [SVision-pro](https://doi.org/10.1038/s41587-024-02190-7) | Reads read-order structure and joins components into complex-SV calls. Its complex-SV evaluation reports region and component/type/position/size matching. | A strong complex-SV caller, but the described benchmark does not score exact phased derivative-path concordance. |
| [gSV, 2026 preprint](https://www.biorxiv.org/content/10.64898/2026.03.02.703663v1.full.pdf) ([code](https://github.com/jhaoae/gSV)) | Calls and joins complex-SV components using read/reference differences and local assembly. Its described simulation evaluation compares event regions and constituent components. | Another relevant caller, not a strawman. The inspected evaluation does not report complete phased event-path correctness; real-data truth is described as incomplete and manually inspected. |

So the only defensible novelty candidate is narrower: **for long events outside the practical local-cluster regime, can a component-complete call still put the components on the wrong phased derivative path, and does that change a concrete gene-copy interpretation?** Short/local phased sequence comparison is not the proposed contribution.

## One public readout and one falsifier

Use the [HPRC Year 1 phased assemblies](https://www.nature.com/articles/s41586-023-05896-x) with the [official assembly release](https://github.com/human-pangenomics/HPP_Year1_Assemblies) and [Year 1 read-data release](https://github.com/human-pangenomics/HPP_Year1_Data_Freeze_v1.0). The releases provide phased diploid assemblies and public HiFi reads/aligned BAMs for 30 HPRC samples; the read release points to public S3/GCP data and PRJNA701308. Restrict to a sample with both released haplotypes and HiFi reads; exclude HG002, HG005, and HG008. Exclude assembly-flagged unreliable intervals. This is a real-read, assembly-path readout, not a claim that the assembly release already contains a qualifying event or caller result. No qualifying event or caller output was confirmed in this pass; generate a focal caller output from the public reads if the selection rule returns an event.

**Fixed first check:** sort eligible sample accessions lexicographically and events by chromosome/coordinate. Take only the first coding-gene-overlapping event that (a) has at least two SV components/junctions, (b) spans more than 10 kb or has separated joins whose full path is not represented by one local cluster, and (c) has resolved paths on both phased assemblies. If none exists, stop. Run a single-locus comparison on that event and its supporting HiFi reads; do not expand to a cohort benchmark first.

**Endpoint.** Compare each called phased derivative path with the corresponding assembly path across the complete event, including component order, orientation, and junction adjacency. The primary positive readout is a **component-pass/path-fail**: component/region matching accepts the parts, but their phased event path is wrong. Then count, from the same reconstructed paths, how many homologs retain one frozen coding transcript for the affected gene (0, 1, or 2). A truth-versus-call change in this count is the biological-interpretation endpoint. This is a sequence-derived gene-copy interpretation, not a claim about expression, phenotype, or clinical outcome.

**Controls.** Apply Truvari and the published SVision-pro/gSV component or region criteria to each read caller's output. Run `vcfdist` and `phab` on phased local representations wherever their documented input and practical span permit; give vcfdist its intended phased inputs and cluster context. Report a long-event comparison outside those documented bounds as an extension question, not as a vcfdist failure. Compare a runnable read-based complex caller on the public HiFi input against the assembly paths; SVision-pro and gSV are the relevant published caller controls, subject to their documented input requirements.

**Kill rule.** Stop this direction before broader benchmarking if the fixed first eligible event does not exist; if the component/region control already rejects the wrong path; if the path discrepancy is fully resolved by vcfdist/phab within supported local scope; or if correcting the path leaves the intact-homolog count unchanged. A surviving event supports only a larger, pre-registered evaluation of long multi-junction path correctness. It does not establish a new general-purpose metric or a clinical effect.

## Why the endpoint could matter

A 2025 family study reports 158 complex events among 1,870 de novo SVs and documents gene-impacting examples, including inversion-loss combinations ([primary study](https://doi.org/10.1038/s41467-025-64722-2)). This supports the relevance of accurate complex-event interpretation, but it does **not** show that component pairing errors are common or alter outcomes. The one-event HPRC check must supply that missing evidence itself.

## Scope of this pass

Three targeted literature searches were used, followed by direct checks of the cited primary papers and official method/data pages. No data were downloaded or analyzed; no caller was run; no code, dependencies, jobs, or Git state were changed. The public event and caller disagreement remain unverified. The recommendation is therefore limited to the single cheap falsifier above.

## Addendum: actionability and residual scope

This addendum supersedes the earlier “fixed first check,” path-error, and gene-copy kill-rule wording above. **The lead is unverified, not yet a runtime-ready cheap experiment.** HPRC’s [assembly release](https://github.com/human-pangenomics/HPP_Year1_Assemblies) exposes an assembly index and per-sample `dipcall_v0.1`/`dipcall_v0.2` QC outputs; the [read-data release](https://github.com/human-pangenomics/HPP_Year1_Data_Freeze_v1.0) provides HiFi reads for 30 samples. That is a candidate metadata route, not a verified compact event catalogue: no junction-grouped event manifest or eligible event has been identified. Therefore there is no finite input candidate for a caller experiment yet. Do not scan assemblies or install/run a caller before that candidate exists.

Prior-art boundary: [TT-Mars](https://doi.org/10.1186/s13059-022-02666-2) is already assembly-based, haplotype-resolved SV validation. It evaluates candidate SVs as independent edit operations against the assemblies; its HG002 results include deletions, insertions, inversions, and duplications, while translocation/break-end calls are ignored. This is strong coverage of per-call assembly-content validation, but not a reported test of component grouping and full derivative-path connectivity. [vcfdist](https://doi.org/10.1186/s13059-024-03394-5) remains a strong phased, clustered sequence-level control. Its >10-kb warning is a memory-cost caution, not an unsupported-scope boundary; with 256-GB nodes, size alone does not establish a gap. Any candidate must be compared using vcfdist’s event-appropriate cluster context before claiming residual novelty.

Count a path as wrong only when the caller **explicitly reports** an event grouping, junction/path structure, or phased component assignment that conflicts with assembly truth. If the caller reports components without that relationship, the path status is **UNKNOWN / not evaluated**, not an error; a component-only score is not a bug. The methodological endpoint, if an explicit claim and finite candidate exist, is reported-path concordance and evaluability—not a required gene annotation. Intact-transcript or dosage consequences may be secondary when relevant, but they are not an automatic pass/kill gate and must not reopen the retired ordinary-annotation premise.

This is a residual hypothesis only. The broader complex-truth evaluation direction remains conditional and unselected in the [October 9 decision](2026-10-09-post-native-value-decision.md); the [October 7 novelty recheck](2026-10-07-novelty-recheck.md) already covers ASVBM, vcfdist, and the 2026 framework comparison. No dataset or caller experiment was performed for this addendum.
