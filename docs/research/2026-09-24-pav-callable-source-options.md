# First-party source options for HGSVC3 PAV callability

**Checked:** 2026-09-24; integrated 2026-09-27.
**Question:** Can per-donor, per-haplotype unsmoothed reference-alignment or callable BED/QC outputs from PAV 2.4.0.1 be obtained for HGSVC3 outside the two already documented `20240307_PAV_VCF` TARs?

## Finding

This source pass did not verify an already-published PAV 2.4.0.1 per-haplotype alignment/callability BED outside those two TARs. It did find a practical first-party route to regenerate one: HGSVC3 distributes phased assembly FASTAs by donor through its public FTP/Globus working area, and the pinned PAV 2.4.0.1 workflow writes per-haplotype reference-coordinate alignment BEDs. This is a bounded finding, not evidence that such outputs are absent from every HGSVC3 or collaborator directory.

One concrete but provenance-risky example is HG00514. HGSVC posted a corrected assembly revision on 2024-10-01 and said dependent files/results would be updated later. Its official manifest lists separate hap1 and hap2 FASTAs at 749,778,038 and 749,433,441 bytes (about 1.50 GB combined), with MD5 checksums. The assembly correction makes it especially important to tie any old PAV outputs to the exact assembly revision before reusing them.
Callability regenerated from the corrected assembly must **not** be paired
automatically with an older merged SV VCF: any intended truth callset needs
its own assembly-revision and reference provenance check first.

## What PAV 2.4.0.1 can generate

The [PAV v2.4.0.1 README](https://github.com/EichlerLab/pav/blob/v2.4.0.1/README.md) documents one analysis directory with `config.json` and `assemblies.tsv`, accepts separate `HAP_h1`/`HAP_h2` input columns, and writes results under `results/{asm_name}`. It also documents optional `FILTER_h1`/`FILTER_h2` BEDs as **assembly-coordinate** QC inputs; those are not reference-coordinate callable masks.

The tagged [alignment workflow](https://github.com/EichlerLab/pav/blob/v2.4.0.1/rules/align.snakefile#L53-L75) writes `results/{asm_name}/align/trim-tigref/aligned_tig_{hap}.bed.gz`. This is PAV's reference-coordinate-trimmed alignment BED for each haplotype and is the best documented unsmoothed alignment-derived starting point. It has already had reference-overlap trimming applied, and the rule has a default minimum trimmed alignment length of 1,000 bp; preserve the exact parameters and, where useful, the earlier `trim-none` BED as well.

The tagged [callability rule](https://github.com/EichlerLab/pav/blob/v2.4.0.1/rules/call.snakefile#L183-L215) consumes that BED plus large deletion, insertion, and inversion intervals and writes `results/{asm_name}/callable/callable_regions_{hap}_{flank}.bed.gz`. The README describes callable outputs as smoothed by 500 bp. The rule's `flank=500` merge can join nearby intervals across a gap of up to about 1,000 bp. For a strict negative-label mask, retain the reference-alignment BED and audit gaps directly; do not treat membership in the merged callable BED as proof that every base was aligned.

## Smallest practical retrieval and rerun

1. Select one donor and the exact reference build used for the candidate coordinates. For the concrete HG00514 path, retrieve only [`HG00514.vrk-ps-sseq.asm-hap1.v2.fasta.gz`](https://ftp.1000genomes.ebi.ac.uk/vol1/ftp/data_collections/HGSVC3/working/20241001_verkko_HG00514_fix/assemblies/HG00514/HG00514.vrk-ps-sseq.asm-hap1.v2.fasta.gz) and [`HG00514.vrk-ps-sseq.asm-hap2.v2.fasta.gz`](https://ftp.1000genomes.ebi.ac.uk/vol1/ftp/data_collections/HGSVC3/working/20241001_verkko_HG00514_fix/assemblies/HG00514/HG00514.vrk-ps-sseq.asm-hap2.v2.fasta.gz), plus their small `.fai`/`.gzi` index files. Verify the downloaded files against the official manifest MD5 values. Inspect the accompanying unassigned/disconnected sequences and assembly QC before interpreting any locus; a candidate represented only on an unassigned contig stays unresolved for haplotype-specific labeling.
2. Use the [publisher no-ALT reference linked by PAV's tagged README](https://ftp.1000genomes.ebi.ac.uk/vol1/ftp/data_collections/HGSVC2/technical/reference/20200513_hg38_NoALT/) for a GRCh38 run, after verifying the exact FASTA checksum and the contig dictionary against the intended HGSVC3 callset. The prior local M5 audit supports sequence identity; preserve the audit and checksum with the new run. Do not substitute a reference merely because it is also called GRCh38.
3. Check out the [PAV v2.4.0.1 source tag](https://github.com/EichlerLab/pav/tree/v2.4.0.1) or its version-pinned container. In a clean one-sample analysis directory, set `config.json` to that reference and `assemblies.tsv` to the two haplotype FASTAs. Add per-haplotype assembly-coordinate filter BEDs only when their provenance and coordinate mapping are verified. Preserve the exact config, assembly manifest, reference checksum, PAV revision/container digest, and command/log.
4. Run the PAV workflow for that donor and retain both per-haplotype `trim-tigref` alignment BEDs and, if generated, PAV's merged callable BEDs as a separate derived product. First confirm the one-sample workflow plan and output paths with the pinned version. The PAV README estimates a full phased-human-genome run at 4.5–5.5 hours, 32 cores, and 64 GB RAM with minimap2; an alignment-target-only run may cost less, but that reduction is not established by the estimate.

This limits assembly retrieval to one donor, but it is still roughly 1.5 GB of phased FASTA plus the reference and requires substantial compute for the documented full run. No FASTA, TAR payload, or cluster job was started in this source audit.

## Limits on negative labels

These outputs would establish assembly-alignment coverage under one PAV/reference/assembly configuration. They would not alone establish that a short-read SV caller had enough evidence to call a variant, nor that absence from a variant VCF means reference genotype. For a proposed negative, require the normalized event interval and prespecified breakpoint flanks to be supported on both phased haplotypes, account for unassigned and filtered assembly sequence, check assembly gaps and PAV trimming, and confirm read-side coverage/mappability. Treat uncertain representation, absent sequence, or any unresolved QC interval as unknown. Validate the frozen negative rule against independent truth before using labels for training or reporting performance.

The strongest uncertainty in this result is distributional: the official working index proves that more first-party HGSVC3 sources exist, but this pass did not crawl all branches or identify a finished per-haplotype PAV 2.4.0.1 BED outside the named TARs. The strongest scientific risk is stale or smoothed callability: the HG00514 note says dependent results were pending, and PAV's callable BED deliberately merges across nearby intervals. Neither a listed assembly nor a generated callable BED is a confident-negative certificate by itself.
